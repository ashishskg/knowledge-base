Foundations

Document structure, metadata, and basic page skeleton.

HTML5 skeleton

Minimum recommended structure for modern pages.

CodeHTML
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>My Page</title>
  </head>
  <body>
    <h1>Hello</h1>
  </body>
</html>
Output

<meta viewport>

Makes the page responsive on mobile (without it, mobile browsers scale strangely).

CodeHead
<meta name="viewport"
      content="width=device-width, initial-scale=1" />
Output

Text & inline semantics

Headings, paragraphs, emphasis, and code.

Headings

Use headings to build a meaningful outline (screen readers rely on it).

CodeHTML
<h1>Page title</h1>
<h2>Section</h2>
<h3>Subsection</h3>
Output

<strong> vs <b>

<strong> adds meaning (importance). <b> is styling only.

CodeHTML
<p><strong>Warning:</strong> Do not share your password.</p>
<p><b>Bold:</b> purely visual emphasis.</p>
Output

<code> and <pre>

Inline code vs preformatted code blocks.

CodeHTML
<p>Run <code>npm run dev</code>.</p>
<pre><code>line 1
line 2</code></pre>
Output

<time>

Machine-readable date/time (useful for SEO, parsing, and screen readers).

CodeHTML
<p>Published <time datetime="2026-03-01">March 1, 2026</time>.</p>
Output

Links & navigation

Internal, external, and in-page navigation.

<a> (external link)

Use target="_blank" + rel="noreferrer" for external new-tab links.

CodeHTML
<a href="https://example.com" target="_blank" rel="noreferrer">
  Visit Example
</a>
Output

In-page anchors

Use id targets for one-page navigation (docs, long pages).

CodeHTML
<a href="#part2">Go to Part 2</a>
...
<h2 id="part2">Part 2</h2>
Output

Images & media

Images, captions, and responsive image patterns.

<img> + alt

alt is required for accessibility; use meaningful alt or empty alt for decorative images.

CodeHTML
<img src="photo.jpg" alt="A sunset over the ocean" />
Output

<figure> + <figcaption>

Use this for images/code/examples that need a caption.

CodeHTML
<figure>
  <img ... />
  <figcaption>Caption text</figcaption>
</figure>
Output

Lists

Choose list types correctly: ordered, unordered, and description lists.

<ul> vs <ol>

Use <ol> when order matters (steps), else <ul>.

CodeHTML
<ul>
  <li>Apple</li>
  <li>Banana</li>
</ul>

<ol>
  <li>Step one</li>
  <li>Step two</li>
</ol>
Output

<dl> glossary list

Great for term/definition UI (FAQs, glossaries).

CodeHTML
<dl>
  <dt>HTML</dt>
  <dd>Markup language.</dd>
</dl>
Output

Tables (data)

Use tables only for real tabular data. Add captions and headers.

<table> with caption and headings

Use <th> for header cells and <caption> to describe the table.

CodeHTML
<table>
  <caption>Scores</caption>
  <thead>
    <tr><th>Name</th><th>Score</th></tr>
  </thead>
  <tbody>
    <tr><td>Asha</td><td>95</td></tr>
  </tbody>
</table>
Output

<thead>, <tbody>, <tfoot>

Helps structure tables for styling, scrolling, and accessibility.

CodeHTML
<table>
  <thead>...</thead>
  <tbody>...</tbody>
  <tfoot>...</tfoot>
</table>
Output

Forms

Inputs, labels, validation, and accessible patterns.

<label> + <input>

Labels make forms usable and accessible (click label focuses input).

CodeHTML
<label for="email">Email</label>
<input id="email" type="email" />
Output

<fieldset> + <legend>

Groups related fields; great for radio groups and sections.

CodeHTML
<fieldset>
  <legend>Plan</legend>
  ...
</fieldset>
Output

<button> types

Buttons default to submit inside forms; set type="button" for non-submit actions.

CodeHTML
<button type="submit">Submit</button>
<button type="button">Just click</button>
Output

<output>

Represents a calculated result (often used with <form oninput>).

CodeHTML
<form oninput="out.value = Number(a.value) + Number(b.value)">
  <input id="a" type="number" value="2" />
  <input id="b" type="number" value="3" />
  <output name="out">5</output>
</form>
Output

Semantic layout

Use semantic regions instead of generic div soup.

Semantic regions

Use <header>, <nav>, <main>, <footer> for meaningful structure.

CodeHTML
<header>...</header>
<nav>...</nav>
<main>...</main>
<footer>...</footer>
Output

<article> vs <section>

<article> is self-contained (shareable). <section> is a themed grouping.

CodeHTML
<section>
  <h2>Features</h2>
  <article>A self-contained card</article>
</section>
Output

Accessibility essentials

What makes your HTML “professional”.

<button> vs clickable <div>

Real controls have keyboard + accessibility behavior built-in.

CodeHTML
<button type="button">Save</button>

<!-- Avoid: <div onclick="...">Save</div> -->
Output

aria-label (when needed)

If a control has no visible label text, add an accessible name.

CodeHTML
<button aria-label="Close dialog">×</button>
Output

Advanced HTML patterns

Modern built-in components and best practices.

<details> / <summary>

Built-in disclosure widget (no JS required).

CodeHTML
<details>
  <summary>More info</summary>
  <p>Hidden content.</p>
</details>
Output

<dialog>

Native modal/dialog element. Needs JS to open and close.

CodeHTML + JS
<button id="open" type="button">Open</button>
<dialog id="dlg">
  <p>Hello</p>
  <button id="close" type="button">Close</button>
</dialog>
<script>
  open.onclick = () => dlg.showModal();
  close.onclick = () => dlg.close();
</script>
Output

<template>

Stores inert HTML that’s not rendered until cloned via JavaScript.

CodeHTML + JS
<template id="tpl">
  <li>Item</li>
</template>
<ul id="list"></ul>
<script>
  const t = document.getElementById('tpl');
  list.append(t.content.cloneNode(true));
</script>
Output

Loading performance

Prefer defer for scripts so HTML parses first.

CodeHead
<script src="app.js" defer></script>
Output
